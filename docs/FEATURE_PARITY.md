# Feature parity matrix

Inventory of the upstream `CopilotKit/OpenDots` `main` build versus this
self-hosted branch. "Status" is deliberately conservative: **Preserved** means
the original code path is intact (or adapted without behaviour change);
**Replaced** means a local implementation reproduces the user-visible behaviour;
**Not equivalent** states exactly what differs.

Automated tests never call a paid provider. Live integrations are implemented but
their live validation is deferred (see the last column).

## Reliability notes

- Incremental journaling is covered by tests that read durable events while a run
  is still streaming, that restart after a crash and keep committed events, and
  that replay a live run without duplicates.
- In-memory streaming is bounded (512 recent events) while SQLite keeps the full
  journal; `connect` replays in 500-row chunks.
- Conversation management is transactional and covered end to end, including
  cascade cleanup, task cancellation, archived-turn rejection, pagination and
  search.
- Automatic Learning analysis is opt-in and can only create drafts; publishing
  always requires the owner.
- Live external integrations remain untested by design (see below).

## Architecture layering

- React app and CopilotKit React SDK: unchanged.
- AG-UI transport: CopilotKit runtime in **local SSE mode** (MIT) with a custom
  `SqliteAgentRunner`; no `CopilotKitIntelligence` instance is created.
- Agent execution: the original TanStack AI `BuiltInAgent` loop and tools.
- Persistence: one SQLite file (workspace + conversations + approvals + learning
  - Slack subscriptions).
- Learning and Slack: local services described in [LEARNING.md](LEARNING.md) and
  [SLACK.md](SLACK.md).

## Explicitly deferred live validation

Per the development brief, no live calls were made to DeepSeek, Ollama, OpenBot,
Slack, Parallel, Composio, or speech providers. Implementations and their mocks
exist; run them against your own services before claiming production readiness.
